# G-Desk 接入

复用现有回调上报进度，不改变训练和评测的执行结果。

## 实施

1. 检查项目规范、启动入口、循环、恢复逻辑、分布式角色和已有日志回调。先确定“完成一个单位”的实际位置及分母，优先复用已有 callback，不重写训练循环。
2. 将 [assets/gpu_task.py](assets/gpu_task.py) 复制到项目合适的可导入位置。它只依赖标准库，运行端需要 Linux `/proc`。已存在时先比较实现和调用方，保留用户修改；不要直接覆盖或额外安装第三方依赖。
3. 按 [references/integration.md](references/integration.md) 接入创建、进度、心跳和结束结果。生产使用默认非严格模式；`strict=True` 只用于明确的接入测试。
4. 每个任务目录只允许一个进程写入。多进程训练由一个控制器／rank 0 汇总实际完成数，登记真正使用 GPU 的所有 worker 身份。不能假定包装器或 torchrun 启动器的 PID 就是 GPU 进程。
5. 检查 G-Desk 配置中对应服务器的 `task_dirs`。当前需显式添加包含 `task.json`、`status.json` 的远端目录，支持 `~/`，不递归发现。仅在请求覆盖配置修改时追加准确目录，保留其他配置；不要为演示启动真实训练或修改无关 SSH 设置。
6. 用临时目录和小型假业务循环验证：正常计数、断点续跑、阶段切换、非有限指标／不可序列化对象、写盘失败、结束写入失败后 flush、训练原始异常仍向外传播。实际 GPU 关联未在 Linux 服务器验证时明确说明，模拟测试不能证明远端绑定成功。

## 不变量

- `update` / `finish` / `flush` 返回是否成功落盘；失败只告警，调用方不得 `assert` 返回值或因此中断训练。`last_error`、`error_count` 和 `pending` 可供诊断。
- 不用训练业务外层的 `except: pass` 达到容错。写入器只隔离自身的普通异常，业务异常、Ctrl+C 和退出信号保持原有传播与退出语义。
- 参数表达式在进入写入器前就会执行。不要为了遥测新增危险张量转换、GPU 同步或数据访问；优先使用业务已有的 Python 标量。必要转换只在遥测专属小范围 try/except 中处理，且要可见告警。
- 进度来自已完成工作，不用 GPU 利用率、等待时长或队列长度猜完成率。不知道总数就不传 total。
- 心跳只说明控制器仍存活，不表示训练推进或没有死锁。每 10–20 秒心跳；高频进度每 2–5 秒合并上报，阶段切换和结束立即写。写入器没有自动心跳或自动节流。
- 一份实例可由线程共享，方法有锁；不要跨进程共享它。同步文件 I/O 没有硬超时，优先本地可写运行目录，不承诺故障网络文件系统永不阻塞。
- 定义冲突不覆盖旧记录。修改实验配置用新 ID／目录；同一实验重启保留定义并生成新 attempt。skill 不授权删除旧目录或历史结果。
